# 子计划 11：全链路集成与实战验证

> "真假对错，走两步才知道"。这是在宣告 "Agent-Group-V2 构建竣工并投入真实生产前" 的全环境仿真验收步骤。

## 目标

验证前后端分而治之，以及公用 mandatory-flow 还有 openspec 枢纽是否真能不阻塞、低消耗地走通一个中型需求闭环场景。

## 前置条件

- 已完成上述 [01] 首项到底层架构 [10] 首项的配置。所有的工具与文本均落座无遗漏且没有语法级别的坏死（如错填了引用）。

## 执行清单

这不用编写任何文本或做大转移修改了，**而是你（以及协作者）需要实际逐个按套路过一遍以探雷。**

### 11.1 Phase A: Max 发起需求阶段测试

- [ ] 让 Max 加载自身并发送用户级提示词拟构一个功能：`发起一个“商品列表页含筛选查询并需要后台导出 Excel”的提案`。
- [ ] **预期结果**：Max 能利用自带技能和指令直接驱动向 `shared/specs/openspec/changes/<某某新造名字>` 下抛出 proposal 和分派好的 tasks。没有被流程死循环锁住；没有未经授权擅自搞设计或拉分支写代码。

### 11.2 Phase B: Ella 设计交接反馈测试

- [ ] 让 Ella 挂载加载，看到由于 Max 提议而在 openspec 产生的需求文件。
- [ ] 指示 Ella 进行该任务。
- [ ] **预期结果**：Ella 不会把产物到处乱写，而是能在对应的 `design.md` 追加自身的内容，并且将针对页面的样式协议和响应式要求等输出到 `shared/handoff/ella-to-jarvis/`。绝对不可抛出各种含前端逻辑的假组件代码（第一性禁止规则）。

### 11.3 Phase C: FE 与 BE 联动标注协同测试

- [ ] 让 Jarvis-FE 阅读并处理来自 tasks 和 handoff 的要求，前端界面模拟产出。
- [ ] 指示 FE 在这里发现"Max写的文档缺了导出Excel要求的特殊文件流后门"，并且通过发起 Cross-Tag 告知这缺失。
- [ ] **预期结果**：FE 在 `fe-to-be` 下打入了标注并且没有跨职责自行跑到业务深水区里瞎写模拟层。
- [ ] 让 Jarvis-BE 阅读并收到来自 `fe-to-be` 接口变动请求。让 BE 提供新接口。
- [ ] **预期结果**：BE 回写契约至 `be-to-fe` 或向 kyle 预审报备。且 BE 没有包揽前面的展示面工作。两者没有爆发冲突并能独立完赛。

### 11.4 Phase D: Kyle 严苛质检关底收尾测试

- [ ] 以 Kyle 的视角加载，读取由后端与前端完结抛出了的通知。
- [ ] 令他依据初始最高规范 `tasks.md` 内验收标准进行测试。
- [ ] **预期结果**：Kyle 通过读取了所有的上下行约定，挑出刺或者验证出一切匹配需求，并且打出符合规范的质检和代码健康度表格并写下。

## 完结评估

- [ ] **Token消耗检验**：整个这圈跑下来，Token是明显降低了，还是因为引用的频繁更严重了？如果偏高，需要再审查并削减各个 `CLAUDE.md` 内公共指令篇幅。或者引入更严密的 token 保护开关避免过大索引。
- [ ] **系统崩溃探针**：有没有某个环节 Agent 崩溃，不停报错寻找一个老目录的路径（比如去找 `designs/`）？有则回到对于人设协议中强行修复补洞并再次验证。

## 注意事项

若能顺趟通过。此时可以将 `agent-group-v2/` 确认稳定版本，将之前的夹杂臃肿旧历史正式封存移除或设为只读以全面铺开新系统。
