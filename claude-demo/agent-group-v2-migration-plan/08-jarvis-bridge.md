# 子计划 08：Jarvis 旧版弃用桥接

> 为旧有的全栈 Jarvis 文件夹保留占位，引导使用者习惯过渡向 `jarvis-fe` 或 `jarvis-be`

## 目标

在 `agent-group-v2/jarvis/` 目录下保留基础的旧式占位文件夹，并在其内部署一份强提示阻断式的 `CLAUDE.md`，帮助团队平滑迁移记忆惯性。

## 前置条件

- 已完成 [子计划05：贾维斯-前端新建](05-jarvis-fe-rebuild.md) & [子计划06：贾维斯-后端新建](06-jarvis-be-rebuild.md)

## 执行清单

### 8.1 建立保留占位

- [ ] 8.1.1 保证存在 `agent-group-v2/jarvis/` 目录。
- [ ] 8.1.2 绝不可在这个目录内部署新的 `skills/` 或复杂的 `PERSONA.md`。

### 8.2 编写阻断指引的 CLAUDE.md

创建一个只有指向说明的短小的 `CLAUDE.md`，用来直接拒绝含糊的任务指派。

- [ ] 8.2.1 编入明确的弃用通告和错误停止逻辑：
  ```markdown
  # ⚠️ 贾维斯 (Jarvis) - 已过时角色
  
  ## ⛔ 致命停止指令 (ZERO EXCEPTION)
  
  如果你当前被挂载加载进了这个文件夹（`agent-group-v2/jarvis/`），**请立即向用户报告报错并停止任何操作。**
  
  ### 给用户的报错文案：
  ```text
  🔴 环境警告：全栈 "Jarvis" 角色已弃用切分！
  
  为了保证专业代码的安全以及缩小前端与后端的任务干扰边界，我们已经进行了团队拆分。请重新重启 CLI 并按以下方式指派项目：
  - 如果你是做界面、交互和客户端：请挂载加载 `jarvis-fe` 文件夹
  - 如果你是负责 Java 后端写库或写底层：请挂载加载 `jarvis-be` 文件夹
  
  这个旧的 Jarvis 路径已不再提供相应的技术堆栈协助，所有的指令皆不执行。
  ```

## 验证清单

- [ ] `agent-group-v2/jarvis/` 是除了该文件外完全空净的目录。
- [ ] 测试用旧版的指定参数试图直接开启该文件夹作为代理人时，立刻产生阻断并收到强指引文本。

## 注意事项

不要将原有的全套旧数据移到这里，保留空壳的唯一作用就是抛出错误并作为使用兼容性软着陆。
