# QA Test Planner

## 描述

专业的测试计划生成工具。帮助测试工程师系统化地创建测试计划、测试用例和验收标准。

## 用途

- 根据需求文档生成测试计划
- 创建详细的测试用例
- 制定验收标准
- 估算测试工作量
- 识别测试风险和依赖

## 使用方法

### 1. 生成测试计划

提供产品需求后，使用该技能生成完整的测试计划：

```markdown
## 测试计划模板

### 1. 测试范围
- 功能测试范围
- 非功能测试范围（性能、安全、兼容性）
- 不在测试范围内的项目

### 2. 测试策略
- 测试级别（单元、集成、系统、验收）
- 测试类型（功能、UI、API、性能）
- 测试方法（手动、自动、探索性）

### 3. 测试环境
- 硬件要求
- 软件要求
- 测试数据准备

### 4. 测试进度
- 里程碑
- 资源分配
- 风险评估

### 5. 交付物
- 测试用例
- 缺陷报告
- 测试报告
```

### 2. 生成测试用例

```markdown
## 测试用例模板

### 用例 ID: TC-001
**功能模块**: 用户登录
**测试标题**: 使用有效凭证登录
**前置条件**: 
- 用户已注册
- 网络连接正常

**测试步骤**:
1. 打开登录页面
2. 输入有效的用户名
3. 输入有效的密码
4. 点击登录按钮

**预期结果**:
- 登录成功
- 跳转到用户主页
- 显示欢迎消息

**优先级**: P1 (高)
**自动化**: 是
```

### 3. 边界值分析

对于输入字段，使用边界值分析：

```markdown
### 边界值测试: 用户名长度

| 测试数据 | 预期结果 | 说明 |
|---------|---------|------|
| 空字符串 | 显示必填错误 | 下限-1 |
| 1个字符 | 接受 | 下限 |
| 5个字符 | 接受 | 正常值 |
| 20个字符 | 接受 | 上限 |
| 21个字符 | 显示长度错误 | 上限+1 |
```

### 4. 决策表

对于复杂业务规则：

```markdown
### 登录决策表

| 条件 | 规则1 | 规则2 | 规则3 | 规则4 |
|-----|-------|-------|-------|-------|
| 用户名有效 | Y | Y | N | N |
| 密码有效 | Y | N | Y | N |
| 账户未锁定 | Y | - | - | - |
| 结果: 登录成功 | X | | | |
| 结果: 密码错误 | | X | | |
| 结果: 用户不存在 | | | X | X |
```

## 测试覆盖率检查清单

### 功能覆盖
- [ ] 所有用户故事都有对应测试用例
- [ ] 所有 acceptance criteria 都被覆盖
- [ ] 正常流程和异常流程都考虑
- [ ] 边界条件已识别

### 非功能覆盖
- [ ] 性能测试场景
- [ ] 安全测试场景
- [ ] 兼容性测试场景
- [ ] 可用性测试场景

### 数据覆盖
- [ ] 有效数据
- [ ] 无效数据
- [ ] 空数据
- [ ] 大数据量

## 输出格式

测试计划应输出为以下文件：

```
test-plan/
├── test-plan.md       # 测试计划文档
├── test-cases.md      # 测试用例集
├── checklist.md       # 验收检查清单
└── schedule.md        # 测试进度表
```

## 提示词示例

### 生成登录功能测试计划

```
请为以下功能生成完整的测试计划：

功能: 用户登录系统
需求:
1. 支持邮箱/密码登录
2. 支持"记住我"功能
3. 连续5次错误密码锁定账户15分钟
4. 支持密码找回
5. 登录后保持2小时会话

请生成：
1. 详细的测试用例（包括正常和异常场景）
2. 边界值分析
3. 验收标准
4. 测试风险识别
```
