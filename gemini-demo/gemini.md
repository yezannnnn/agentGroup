# 项目认知与问题解答

## 1. 这个项目是做什么的？
这个项目是一个**多AI团队协作系统（aiGroup）**。它独创性地将不同维度的研发工作分配给四个具有特定“人设”和专业技能的AI代理：
- **Max（麦克斯）**：项目经理 & 产品顾问，负责进度把控、需求分析和任务分配。
- **Ella（艾拉）**：UI/UX 设计师，负责视觉与交互设计。
- **Jarvis（贾维斯）**：全栈开发工程师，负责前后端代码编写与架构实现。
- **Kyle（凯尔）**：质量保证工程师（QA），负责代码审查、功能测试与验收。

项目通过严格隔离各自的职责边界以避免AI出现能力重叠与过度设计，并利用一套基于复杂度的模型分类和**Token优化策略**（如任务强制分解、状态文件增量检查）来大幅度节约API调用成本。AI之间通过一套 `shared/` 共享工作区同步信息（如 `status.json`、`todos.md` 等），实现高度自动化的软件开发与系统化协作。

## 2. 我现有一些后端的规范和检查点内容，如何添加到jarvis或kyle的skill中？
在本项目中，各个 AI 的技能（Skill）本质上是带有特定 YAML Frontmatter 说明的 Markdown 描述文件。根据你的规范文件 `gemini-demo/backend-review.md`，你只需将其归档到对应 AI 的专属技能包目录中即可被他们识别为“固有技能”使用。

**建议存放位置**：
这属于“代码审查”和“规范排查”范畴。根据职能设定：
- **首选 Kyle**（专注于质量保证与测试）：将其复制到 `kyle/skills/senior-qa/` 目录下（例如命名为 `backend-review.md`）。
- **备选 Jarvis**（开发阶段的查漏补缺自纠）：也可以将其放入 `jarvis/skills/` 中，让贾维斯在进行后端开发时可以直接调用指令进行自检。

**操作方法**：
将该 `.md` 文件放到上述技能目录。由于文件头部自带了 `name: backend-review`，这些 AI（例如通过 Claude CLI 等工具启动后）会在工作区内自动检测并装载这个能力。在你的提示词中只需唤起类似“使用 backend-review 技能 Review 这个文件”或者按 `jarvis` / `kyle` 的预设斜杠命令 `/review`，就会自动执行这套规范。

## 3. 我是在window11使用powershell，在日常开发中，如何使用？
项目中提供的快捷启动脚本为 Shell 脚本（例如 `./start-jarvis.sh`），在 Windows 11 PowerShell 默认环境下有以下几种高效结合方式：

- **方案一：使用 Git Bash 运行（推荐）**
  如果你已安装了 Git，可以直接在项目根目录打开终端使用 Bash 运行启动脚本：
  ```bash
  bash start-jarvis.sh
  ```
- **方案二：结合 PowerShell 的进入目录法启动**
  如果不便使用 bash，因为底层依赖的是如 `claude` (Claude Code) 这样的跨平台 CLI 工具，你可以直接在 PowerShell 中进入对应角色目录，手动唤醒：
  ```powershell
  cd jarvis
  # 参考 sh 脚本逻辑，直接附带模型参数启动
  claude --model claude-sonnet-4-20250514
  ```
日常开发中，唤醒指定的 AI 后，因为当前目录处于他们的人格预设下，你可以直接向 AI 甩过去前端或后端独立仓库的“**绝对路径**”，让 AI 跨项目读取、编写或 Review 代码。

## 4. 前后端分两个git仓库，本项目也是一个git仓库，项目目录结构是什么样的？
本仓库（`agentGroup`）纯粹是 **AI 团队的大脑、规则与记忆管理中心**，并不包含任何前后端实际业务代码。当前的核心组织架构如下：

```text
agentGroup/                  # 本仓主目录
├── max/                     # 麦克斯(PM/架构)的独立配置、记录与专属技能
├── ella/                    # 艾拉(UI/UX)的独立配置、记录与专属技能
├── jarvis/                  # 贾维斯(全栈开发)的独立配置、记录与专属技能
├── kyle/                    # 凯尔(QA/测试)的独立配置、记录与专属技能
│   ├── CLAUDE.md            #  -- 每个角色对应的系统级Prompt行为指令
│   ├── PERSONA.md           #  -- 每个角色独特的人格预设
│   └── skills/              #  -- 每个角色具体的Skill Markdown库
├── shared/                  # ⭐角色之间的跨域共享区（核心）
│   ├── status.json          #  -- 通知与共享状态 (解决上下文割裂问题)
│   ├── tasks/               #  -- 统一的任务拆分和会议记录
│   └── reviews/             #  -- Review结果及报告
├── scripts/                 # 工具脚本（如文件更新探测、文件清理等）
├── gemini-demo/             # (用户存放示例和规范文件的位置)
├── README.md                # 运作手册与边界说明
└── start-*.sh               # 针对各个AI工作台的快捷进入脚本
```

**多仓库物理拓扑图示**：
在你的本地计算机中，实际物理结构会类似于：
```text
D:\git_repo\
   ├── frontend-repo\       # 你的前端代码仓库 (被动受控)
   ├── backend-repo\        # 你的后端代码仓库 (被动受控)
   └── agentGroup\          # 本项目仓库 (AI中控和指挥台)
```
当你在 `agentGroup` 下拉起对应 AI 时，通过向 AI 下发指令令其跨目录检索 `../frontend-repo/` 和 `../backend-repo/`，实现“一个中控指挥台，修改多个业务仓”的开发模式。
