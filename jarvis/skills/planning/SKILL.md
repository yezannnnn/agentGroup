# Planning with Files Skill

使用文件进行持久化任务规划，实现 Manus AI 风格的任务管理。

## 核心理念

Claude 的上下文窗口是易失性 RAM，文件系统是持久化磁盘。重要信息应该写入磁盘。

## 三个核心文件

### 1. task_plan.md - 任务计划
记录：
- 任务目标
- 拆解的步骤
- 已完成进度
- 下一步行动

### 2. findings.md - 研究发现
存放：
- 调研资料
- 中间代码片段
- 临时想法
- 长文本内容

### 3. progress.md - 进度日志
跟踪：
- 当前状态
- 错误记录
- 已尝试的方案
- 时间戳记录

## 五大关键规则

### 1. 先创建计划
永远不要在没有 `task_plan.md` 的情况下开始复杂任务。

### 2. 2-行动规则
每进行两次搜索、查看或浏览操作后，立即将关键发现保存到磁盘。

### 3. 读后再决定
在做任何重大决策前，重新阅读计划文件以保持目标在注意力窗口中。

### 4. 行动后更新
标记完成的阶段，记录错误，注明创建的文件。

### 5. 绝不重复失败
记录已尝试的方案并改变方法。

## 错误处理协议（3次机会）

1. **第一次失败**：诊断问题，尝试替代方案
2. **第二次失败**：重新思考问题，尝试完全不同的方法
3. **第三次失败**：向用户升级，请求指导

## 会话恢复

在 `/clear` 或新会话后：
1. 读取 `task_plan.md` 恢复任务目标
2. 读取 `findings.md` 恢复研究背景
3. 读取 `progress.md` 了解当前状态
4. 继续执行任务

## 使用示例

### 开始新任务
```
用户：帮我开发一个用户认证系统
→ 创建 task_plan.md
→ 规划阶段和步骤
→ 开始执行
```

### 执行过程中
```
完成调研 → 更新 findings.md
完成一个阶段 → 更新 progress.md
遇到错误 → 记录到 progress.md，尝试替代方案
```

### 跨会话继续
```
新会话 → 读取三个文件 → 继续执行
```

## 优势

- **上下文持久化**：解决 AI 上下文丢失问题
- **目标锚定**：保持任务焦点
- **可追溯性**：完整记录思考过程
- **可恢复性**：随时从中断处继续
